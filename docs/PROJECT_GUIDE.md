# 项目结构、角色与开发规范

本文描述 2026-10-07 当前代码，适用于已清空业务数据的新环境。此前验收文档中的账号、业务记录和测试结果属于历史记录，不代表当前数据库仍有这些数据。

| base             | 公共响应、异常、JWT 鉴权、消息协议和基础工具       | —        | —                     |

业务模块沿用 API → Service → Model：控制器接收请求，服务执行业务及事务，Model 保存 DTO 和持久化对象；SQL 放在 MyBatis Mapper 中。消息使用 RabbitMQ，服务发现和外部配置使用 Nacos。对象存储使用固定摘要的 `pgsty/silo` 镜像。

## 三角色与教学空间

| 角色             | 开户方式                           | 主要权限                                                       |
| ---------------- | ---------------------------------- | -------------------------------------------------------------- |
| 学员 student     | 学员端公开注册                     | 浏览课程、试学、本人选课和订单、有效资格下学习、提交老师申请   |
| 老师 teacher     | 平台管理员创建，或本人申请审核通过 | 管理本人教学空间的课程、目录、讲师介绍与媒资，提审、发布、下架 |
| 平台管理员 admin | 部署人员受控初始化                 | 审核课程和老师申请，创建、查询老师账号                         |

新老师开户时自动创建独立教学空间。底层仍以 `company_id` 表示教学空间，服务端从已验签身份读取，不接受客户端伪造归属。当前并未加入额外的课程负责人机制；若人为把多个老师绑定到同一空间，他们会共享该空间的教学权限。

老师账号与学员账号相互独立。课程中的“讲师介绍”是展示资料，不是登录账号。管理端两个角色共用入口，前后端都校验权限。公开注册不能取得管理员权限。

## 核心流程

1. 老师开户 → 上传封面和视频 → 视频转码可用 → 保存课程草稿。
2. 编排章节、小节、讲师介绍及媒资 → 提交审核 → 管理员读取冻结快照并审核。
3. 审核通过 → 老师发布 → 可靠消息同步 Search 和 Learning。
4. 免费课程选课成功后按有效期学习；免费课程到期后，仅本人可按最新发布规则续期，已改收费不能免费续期。
5. 收费课程生成订单和沙箱二维码 → 实际交易确认 → 可靠支付事件 → Learning 幂等开通资格 → 回执。
6. 匿名试学仅开放正式发布且标记为试学的小节；其他小节要求学员有效资格，Media 签发短期播放地址。

保存草稿不会自动提交审核。审核中或已发布课程的修改受状态限制；修改已通过审核的内容需要重新审核。真实支付宝付款与公网异步回调仍按用户约定保留未验收状态。

## 空库初始化

先执行 [INIT_DATABASES.sql](sql/INIT_DATABASES.sql)，初始化六个数据库、表结构、分类、字典和角色；脚本不提供默认用户或默认管理员密码。

首个管理员由数据库管理员受控创建：使用 BCrypt 密码散列、用户类型 `10203`、启用状态 `1`，并关联启用的 `admin` 角色。也可以先通过学员端注册专用账号，再由部署人员在数据库中调整该账号类型并建立角色关联；调整后退出并重新登录。不要使用日常学员账号承担平台管理身份。

初始化结构不等于完成部署。还需要基础设施、私有存储桶、Nacos 模板、各 Java 进程环境变量和服务启动。操作步骤见 [DEPLOYMENT.md](DEPLOYMENT.md)。

## 注解与中文注释

- `@Tag` 表示接口分组；`@Operation` 的 summary 使用简短动作名称，description 说明权限、输入和业务限制。
- `@Schema` 描述真实字段含义、实际类型和字典编码；已有必填校验与文档标记保持一致。密码标记为只写入接口文档，并保留日志脱敏。
- `@Valid`、`@Validated` 与校验约束决定参数校验行为，不能仅为整理格式而添加业务限制。
- `@Transactional` 保留已有事务边界、回滚规则和锁定顺序；声明事务不能替代实际行锁与幂等校验。
- Spring 映射、MyBatis 映射、消息与安全注解都影响运行行为，只有确认存在具体问题时才修改。
- 中文注释解释归属、状态、事务、快照、有限重试等业务规则，避免写“处理业务请求”等泛化说明。
- 全部文本使用 UTF-8；Java 四空格，Vue、TypeScript、CSS 两空格。使用现有 Prettier 和 Java 插件，不增加格式化依赖。

## 构建与校验

```sh
npm ci
npm run format
npm run format:check
python scripts/check-utf8.py

mvn -f parent/pom.xml install
mvn -f base/pom.xml install
mvn -f auth/pom.xml install
mvn -f content/pom.xml install
mvn -f media/pom.xml install
mvn -f search/pom.xml install
mvn -f learning/pom.xml install
mvn -f orders/pom.xml install
mvn -f gateway/pom.xml verify

npm --prefix frontend-admin ci
npm --prefix frontend-admin run build
npm --prefix frontend-student ci
npm --prefix frontend-student run build
```

使用 JDK 21 和已安装的 Maven。无根聚合 POM；先安装 parent、base，再构建业务模块。构建通过只证明代码可编译，不能替代数据库、消息、上传、付款及页面真实验收。配置模板和格式整理不会自动同步到运行中的 Nacos 或 Java 进程。
