# 课程发布统一流程与重构目标

## 依据与范围

按用户提供的《第4章+课程发布v3.1》《课程发布-部署门户文档》和《项目总结》整理目标流程：课程预览、审核、正式发布，以及 Redis、Elasticsearch 的可靠同步。保留当前项目的 Learning 目录同步、三角色权限和事件版本保障。

本文定义重构目标，不代表以下能力均已实现。按用户最新要求，课程预览和正式详情使用 Vue 页面及 API，不引入 FreeMarker 或课程 HTML 静态化。

## 流程总览

制作草稿与预览 → 提交审核快照 → 平台管理员审核 → 老师发布 → 本地事务保存正式快照与事件 → 后台同步 Redis、Elasticsearch、Learning → 汇总阶段状态 → 全部成功后归档任务。

发布、重新发布和下架共用可靠事件机制。课程业务状态与同步任务状态分别管理：数据库提交表示发布已受理，三个同步阶段成功才表示同步完成。

## 1. 制作草稿与预览

老师维护本人教学空间的课程基本信息、营销规则、讲师介绍、章节及媒资。Content 汇总草稿数据生成预览；预览仅供有权限的老师和管理员检查，不生成正式发布事件，不对外开放草稿视频。

Vue 页面通过授权 API 展示草稿预览、审核快照及正式课程详情，明确各入口的数据来源，保证预览不暴露未发布内容。

## 已确认的业务规则

用户已确认以下规则，作为本轮实现与验收依据。

### Redis 课程详情缓存

Content 管理正式公开快照缓存，Search 独立管理查询缓存。发布事件提交后主动同步 Redis；详情 API 优先读缓存，未命中读取 course_publish 并回填。缓存不包含草稿、个人学习资格或签名地址，采用可配置的有限 TTL 和抖动。写入与回填均需版本保护；下架保留版本标记，防止迟到发布事件恢复课程。查询故障可回源数据库，同步故障保留任务重试。公开详情回源必须检查正式发布状态；缓存未命中或 Redis 故障不能绕过下架判断。内容 TTL 与版本保护分开管理，版本/下架标记不得仅随内容缓存过期而丢失；标记缺失时以持久化版本和状态核查后恢复，旧事件不能重新激活课程。

### 审核编辑与重新提审

审核中允许编辑草稿，但禁止重复提审。管理员始终审核冻结快照；通过后可发布该快照，即使草稿已有后续修改。若要发布新草稿，必须重新审核。已发布课程在修改和提审期间保持原正式版本。页面区分未提交草稿修改、审核版本和发布版本。

### 任务归档及保留

Redis、ES、Learning 全部成功后，事务内写入 mq_message_history 并移除待处理任务，以事件 ID 保证幂等。失败任务保留，重复和晚到回执可识别历史记录。归档后仍可查询本人教学空间的发布、下架及同步结果。第一轮不自动删除历史任务；重构完成后再确定审计需求及保留期限。

## 2. 提交审核与快照隔离

提交前检查归属、课程完整性、目录、媒资可用性及收费规则。在本地事务内保存 course_publish_pre 审核快照并更新审核状态。

按教程目标，提交后可继续编辑草稿，管理员始终审核冻结快照；审核完成前不得重复提交。该规则与当前部分编辑限制存在差异，实施时需明确草稿版本，并保证发布只读取审核通过的快照，后续草稿修改不混入正式内容。

## 3. 平台审核

平台管理员检查冻结内容及视频，保存审核结论与原因，并记录 course_audit。通过后允许老师发布；驳回后修改并重新提审。审核通过不自动发布，老师不能审核自己的课程。

教程中的手工修改数据库状态只属于教学测试方式，当前正式流程继续通过审核接口执行。

## 4. 正式发布与可靠任务

老师发布时再次核查身份、教学空间、审核状态和快照版本。在同一数据库事务内：

1. 将审核通过的快照保存到 course_publish。
2. 更新课程发布状态。
3. 保存包含事件 ID、课程 ID、版本、发布状态及不可变快照的持久化发布任务。

事务提交后返回“发布已受理，正在同步”。Redis、ES 和 Learning 的同步操作放在事务外，任何单项失败都通过任务恢复，不以回滚全部外部系统为前提。

## 5. 分阶段同步

| 阶段          | 目标操作                                  | 数据归属                                                    |
| ------------- | ----------------------------------------- | ----------------------------------------------------------- |
| Redis         | 主动写入正式课程快照 JSON，供公开详情读取 | Content 管理公开课程详情缓存；Search 继续管理自己的查询缓存 |
| Elasticsearch | 建立或更新可搜索的正式课程文档            | Search 消费版本化事件并返回回执                             |
| Learning      | 更新正式课程目录及发布状态副本            | Learning 消费版本化事件并返回回执                           |

调度器扫描待处理任务并原子抢占；每个阶段记录成功、失败原因和重试状态。重试跳过已完成阶段，外部写入仍需幂等，因为进程可能在写入成功、记录阶段状态之前退出。使用同一持久化快照，不能重试时读取最新草稿。

保留当前定时投递和 RabbitMQ 能力；按教程的任务语义组织流程，不引入 XXL-Job。Redis 详情缓存需要新增读取入口及失效策略，不能只增加写入。Search 更新 ES 时继续推进其缓存版本，使列表和搜索详情缓存失效。

三个阶段相互独立，没有必须依次完成的要求。RabbitMQ 发送确认仅证明投递成功，ES 和 Learning 必须收到消费成功回执；Redis 阶段必须确认版本化写入成功。任一业务阶段未完成都不能归档。

## 6. 完成与恢复

### 阶段记录与失败重试

复用当前任务抢占租约、有限重试、失败原因记录及手动恢复能力。Redis、ES、Learning 各自记录状态；重试只处理未完成阶段。队列发送确认是投递状态，不能替代业务阶段成功。

外部写入保持幂等，覆盖“外部写入成功但本地状态未记录”的中断窗口。失败回执不能覆盖已成功阶段，成功回执允许恢复此前的失败。重试耗尽后保留任务和错误，由有权限的老师重新安排本人教学空间的任务；不能删除失败任务或伪报成功。

进程退出后，抢占租约到期允许其他实例恢复处理。重投使用原事件 ID 和不可变快照，不生成新发布版本。重新发布则创建新事件及更高版本。

### 全部成功后归档

Redis、ES、Learning 三个阶段全部成功后，在一个本地事务内：

1. 锁定任务并再次确认完成条件。
2. 以原事件 ID 幂等写入 mq_message_history，保存快照、阶段结果、重试信息与完成时间。
3. 从 mq_message 待处理表移除任务。

归档失败可重试，不重新执行已成功业务阶段；历史表写入和待处理表删除必须同时提交或同时回滚。并发归档及重复回执不能产生重复历史记录。

回执处理需要识别待处理任务和已归档事件：对可验证的已归档事件，重复或晚到回执正常确认；对不存在的事件按明确的异常策略处理，不能全部当作成功。前端同步状态查询兼顾待处理表和历史表，归档后仍能查看结果。第一轮不自动删除历史任务，保留期限在重构后结合审计需求与数据量确定。

## 7. 门户展示与受保护操作

Vue 门户通过 API 获取课程搜索结果、正式详情和目录。公开详情 API 使用正式快照及 Redis 缓存，不读取草稿；选课、订单和播放继续通过各自业务 API 执行。

公开响应不包含账号、学习资格或签名播放地址。受保护视频由 Learning 核查资格后通过 Media 获取短期签名地址，对象存储保持私有。

## 8. 重新发布与下架

重新发布产生更高版本的快照和事件，同步替换 Redis、ES 和 Learning 副本。下架同样产生事件，使公开课程缓存失效、搜索结果隐藏，并同步 Learning 状态。

所有投影必须拒绝旧版本覆盖新版本。ES 与 Learning 复用当前版本判断；Redis 需设计版本比较或等效机制，避免迟到任务恢复旧内容。

### 已确认的下架业务规则

- 下架后隐藏搜索结果，禁止新选课、新订单和匿名试学。
- 保留已有选课、学习资格和订单记录，不随下架删除。
- 下架期间暂停所有学员播放，包括已获得资格的学员；重新发布后只有仍有效的资格允许继续学习。
- 下架期间禁止免费续期。
- 未支付订单不能仅凭下架直接标记关闭，先核查支付宝实际交易状态，再按订单关闭规则处理。
- 已实际支付的交易按原订单快照完成确认、可靠事件及资格开通，页面提示课程下架、暂不可学习。下架不能作为伪造未支付或忽略真实收款的依据。
- 自动退款及下架补偿不纳入本轮，下架不等同于退款。用户已确认下架期间资格有效期继续计时、不自动顺延，详见 [学习有效期规则](COURSE_ENROLLMENT.md)。

## 验收标准

发布状态区分“已受理”“同步中”“同步失败”“同步完成”。完成必须覆盖 Redis、ES、Learning 三个阶段，不能仅凭数据库提交、队列确认判断。

验证发布、重新发布和下架；分别模拟 Redis、ES、Learning 不可用，确认恢复后完成同步。验证重复事件、乱序事件、并发发布和进程退出不会覆盖新版本、重复延长学习资格或混入草稿。确认公开 API 不泄露受保护数据，视频仍需资格校验。

补充验证任务抢占租约到期恢复、自动重试耗尽与手动恢复、归档事务失败、并发归档、重复/晚到回执，以及归档后的状态查询。完成记录只能归档一次，失败任务不能被归档为成功。
