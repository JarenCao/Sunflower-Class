## 课程状态流转

- 创建课程：`audit_status=30402`、`status=30501`。只有未提交或驳回，且课程未发布或已下架时可以提审；提审后仅将基础表 `audit_status` 和预发布表 `status` 改为 `30403`。
- 审核中禁止编辑课程信息、教学计划和媒资绑定；已发布课程须先下架再编辑。未发布或已下架课程审核通过后若发生编辑，审核状态回到 `30402` 并删除旧预发布快照，必须重新提审。
- 发布要求基础表审核状态与预发布快照均为 `30404`，发布操作只修改发布状态，不代替审核员给出结论。未改内容的已下架课程可使用原正式快照重新上架；下架不改变审核结论。
- 审核员通过/驳回接口仍属于下一开发项；现有 `sunflower.company-id` 仅是开发期机构身份配置。

图片上传成功即为 20302，视频转码成功才为 20302。消费者与定时补偿共用 `media.transcode.max-attempts`，默认最多三次失败；补偿只选未耗尽次数的失败任务，事务提交后才投递。达到上限保留 20303，需要排除故障后人工重试。

章节层级 1/2、布尔标志 0/1、计数、主键、分类 ID，以及尚未接入业务的 MQ 阶段执行标志，不属于上述业务字典，未为了凑五位而转换。

## 历史迁移规则

- 等级 204001/204002/204003 与早期 grade 字段的 200001/200002/200003，按初/中/高级映射到 30301/30302/30303。只在 grade 字段应用，不跨字段替换。
- 教学模式 200002/200003 → 30101/30102。
- 收费 201000/201001、70101/70102 → 30201/30202；701 仍保留为选课类型字典，不修改字典本身。
- 发布 203001/203002/203003 → 30501/30502/30503。发布快照中旧错误值 30404 → 30502。
- 课程 80 的基础表 status=30403 为历史误写；同时存在审核通过和发布快照证据，修复为 30502。其他无法确认的错误状态会中止迁移。
- 教学计划 0/1 → 10102/10101；计划 21 的旧“已发布”203002归入正常记录10101。
- 媒资/任务 0/1/2/3/4 → 20300/20301/20302/20303/20304；普通素材旧待处理改为可用。
- 同步转换 course_publish 与 course_publish_pre 的 market/teachplan JSON 快照，更新状态列默认值并补充 203 字典。

## 运行与回滚

脚本为 `scripts/NormalizeStatusCodes.java`，PowerShell 入口 `scripts/normalize-status-codes.ps1`。依赖本地 MySQL JDBC 和 Jackson JAR，版本与路径在入口列明。凭据只在内存中从 Nacos 读取，不写入源码或输出。

```powershell
$env:NACOS_SERVER_ADDR='localhost:8848'
$env:MAVEN_REPO='D:/maven/repository'
./scripts/normalize-status-codes.ps1 check
# 先停止 Content、Media，确保无并发写入，再执行 apply
./scripts/normalize-status-codes.ps1 apply
./scripts/normalize-status-codes.ps1 verify
```

本机已执行 apply，不要重复运行。脚本遇到同名备份即停止，防止覆盖原始数据。原表数据保存在各自数据库的 `bak_20260925_*` 表；数据转换在一个事务中完成，DDL 默认值更新由 MySQL 单独提交。

需要撤销本次迁移时，先停止服务并确认迁移后没有需要保留的新编辑，再执行 `rollback`，随后恢复迁移前应用版本。rollback 只恢复备份行的迁移字段及快照，不删除迁移后新增业务数据；新增记录须按旧版本兼容要求另行处理。备份表保留，确认验收后再人工清理。

媒资删除先持久化 20305，取消转码后清理对象和元数据；清理失败保留删除中和原因，可再次删除重试。引用中的文件返回 409，不进入删除状态。

## P2 机构申请与交易状态

机构申请使用 system.dictionary 的 401 字典：40101 待审核、40102 通过、40103 驳回，仅用于 users.institution_application.status；旧 company.status 空值保留，不套用申请状态。

orders.status 使用 60201 未支付、60202 已支付、60203 已关闭、60204 已退款、60205 已完成；pay_record.status 使用 60301 未支付、60302 已支付、60303 已退款。课程订单类型为 60101。订单创建、二维码生成及前端点击都不能直接写成已支付。

Learning 选课类型沿用 70101 免费、70102 收费；选课状态沿用 70201 成功、70202 待支付，资格为 70301 有效、70302 无资格、70303 已过期。真实支付确认及幂等开通完成后才由待支付转为成功。
