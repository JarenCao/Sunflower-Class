> 本文记录历史实现。2026-10-05 已简化为学员、老师、平台管理员，最新权限及验收结果见 [三角色权限与流程](ROLE_SIMPLIFICATION_PLAN.md)。

日期：2026-10-01。状态：实现及真实联调完成，等待用户验收。本次仅完成角色授权，不开始选课功能。上一次独立认证微服务及三层架构已由用户确认验收。

## 行为

- 保留 API → Service → Model 三层结构，复用已有 Spring Security、JWT、JDBC、MyBatis、审核流程与 Vue 页面，没有新增框架或另一套权限服务。非显然业务规则添加中文注释。
- 机构只维护本机构课程与媒资，可提交审核、发布和下架；不能通过或驳回课程。既有机构归属校验保留，角色校验同时覆盖业务入口。
- 审核员独立登录，仅显示审核工作台，可跨机构读取提交快照及审核历史、通过或驳回待审课程。查看快照为只读；不能进入机构编辑页面或调用编辑、删除、发布、上传、分片接口。
- 审核人只取 JWT 中的真实显示名，忽略请求传入的冒充姓名。学生旧角色中的 admin/super 关联不产生机构或审核权限；普通管理员也不自动取得审核权限。
- 学员端登录只接受 student，个人学习和订单路由要求学生身份；机构与审核接口对学生返回 403。公开课程与公开目录仍可匿名访问。选课、支付和受保护视频的学习资格尚未开发。
- 发现原数据有五条审核中课程缺少提交快照。队列只列出有效提交记录，原状态和课程内容保留；已通过课程可读取正式发布快照。机构完善课程后可重新提审。

## 已授权账号

用户明确批准在本机 users 数据库新增 `sunflower-reviewer`，授予跨机构只读审核队列/快照与提交审核结论的权限。已创建启用 reviewer 角色、管理员类型验收用户及唯一关联；不改变原用户授权。随机密码仅保存在忽略文件 `.runtime/reviewer-account.json`。角色迁移、部署与授权规则见 [认证部署](AUTHENTICATION.md)。

## 用户验收步骤

1. 机构端 `http://localhost:5173/login`：退出已有身份后，用 `sunflower-reviewer` 及本机密码文件登录。只能进入审核工作台；切换已通过，打开“查看快照”和“审核记录”。
2. 用原 `sunflower-institution` 登录：可维护本机构课程、提审和发布，不能进入审核工作台或自行审核。
3. 需要验证结论流转时，以机构账号新建完整临时课程并提审，再切换审核员执行驳回/通过；切回机构确认状态和审核历史。不要改动原课程仅为测试。
4. 学员端用原 `sunflower-student` 登录：公开课程可浏览，机构/审核接口不可调用。本次不验收选课或播放资格。

角色修改在新登录时生效，已签发 JWT 不作即时撤销，最长三十分钟过期。下一项免费/收费选课须等用户确认本次验收并明确继续。
