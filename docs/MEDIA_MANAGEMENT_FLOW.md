# 媒资管理统一流程与重构目标

## 依据与范围

结合《第3章媒资管理模块v3.1》与当前 Media、Content、Learning 实现整理。保留上传、分片续传、完整性校验、转码、失败重试、超时恢复与成功归档，同时保留教学空间隔离、私有存储、播放授权和安全删除。

用户已明确不引入 XXL-Job。转码任务保存并提交事务后立即通过 RabbitMQ 投递；Spring @Scheduled 负责遗漏投递、发送失败、到期重试和处理超时的补偿，数据库原子更新控制投递权与处理权。本文是统一方案与静态核查结果，不代表完成新的代码改造或真实环境验收。

## 流程总览

图片/普通文件：授权上传 → 对象存储写入 → 数据库登记 → 绑定课程 → 授权访问。

视频：检查文件与分片 → 上传缺失分片 → 合并及校验 → 保存原文件和转码任务 → 事务提交后立即投递 → 消费者抢占转码 → 上传产物 → 更新可用状态并归档任务 → 绑定课程 → 授权播放。

文件删除：归属与引用核查 → 标记删除中并取消任务 → 清理对象和产物 → 清理数据库记录；失败保留恢复状态。

## 已确认的上传与分片清理规则

- 普通上传支持业务允许的非视频文件；视频采用分片上传。
- 后端校验类型、整文件大小、分片大小及数量限制，并通过 API 向前端提供规则；第一轮核查并沿用当前有效配置。
- 上传会话记录教学空间归属、文件摘要、整文件大小及最后活动时间，支持查询分片和断点续传；会话是重构目标，不能视为现有实现。
- 合并成功后清理临时分片，清理失败由定时任务补偿。
- 未完成会话连续七天无活动后到期清理，期限可配置；有效期内可续传，到期后明确提示重新上传。
- 清理与上传、合并协调，不能仅靠一次状态查询避免竞态；实际删除前确保会话不在活动处理期间。
- 到期清理只针对临时分片，不删除已登记原文件、转码产物或其他会话的文件。

## 1. 上传与文件登记

老师只能管理本人教学空间的媒资。校验文件类型、大小、名称及摘要等参数，上传到兼容 S3 的对象存储，在 media_files 保存文件元数据。

网络上传不放入长时间数据库事务。对象上传成功但登记失败时，需要清理残留或保留可识别的恢复依据。摘要用于内容识别和完整性校验，不是访问凭证；相同摘要不代表其他老师可以查看或复用该文件。

普通上传与视频分片上传分开处理；是否需要转码根据当前格式规则判定，不能将所有文件都加入转码队列。

## 2. 分片续传与合并

前端计算整文件摘要，查询已完成文件及已上传分片，只上传缺失分片。检查、上传和合并均校验教学空间及参数，避免跨空间枚举或覆盖。

合并前确认分片齐全，合并后核对整文件大小和 MD5。校验通过后保存原文件及媒资记录，并为需要转码的视频建立 media_process 任务。清理临时分片；失败不返回可用状态，残留清理失败需有后续恢复方式。

同一上传的并发合并和重试必须幂等。文件记录与需要的任务记录应保持事务一致，不能出现记录已提交但任务永久丢失的状态。

## 3. 事务提交后立即投递与定时补偿

文件记录和转码任务先在本地事务中保存。事务提交成功后立即尝试通过 RabbitMQ 投递，不能在提交前发送，避免消费者读不到任务或数据库回滚后仍执行转码。事务回滚不投递。

立即投递与 VideoScheduler 补偿扫描共用同一个投递入口：根据数据库条件原子抢占投递权，读取持久化任务，发送消息并按现有确认机制记录结果。两个入口不能分别实现状态转换或无条件发送。投递抢占使用短数据库事务，网络发送放在事务外。

任务记录是恢复依据。提交后回调未运行、进程退出、RabbitMQ 不可用或确认结果丢失，都由定时扫描恢复；立即发送异常不能撤销已提交任务，接口不得让用户误以为文件需要重新上传。上传成功与转码尚未开始分别展示。

Spring @Scheduled 定期扫描未投递、投递超时和到期重试任务，同时处理转码超时补偿。当前扫描周期默认五秒，最大实际转码失败次数默认 3 次，重试间隔默认 30 秒。发送失败不计为实际转码失败，投递结果不确定时允许重投。

多实例依靠数据库条件更新与投递租约控制并发，不依赖本地锁。消息可能重复，消费者仍需独立抢占转码处理权，核查任务和文件状态，跳过已完成或已取消任务。消息发送确认不能作为转码完成依据。

## 4. 转码执行与并发保护

消费者读取持久化任务，核查文件未删除、任务未完成且仍可处理，原子更新为处理中并记录本次处理标识，再下载源文件并调用 Docker/FFmpeg。

执行设置超时并管理临时文件；成功产物上传对象存储后，只有仍持有处理权的消费者可以提交结果。不能将转码、下载和上传全部包在数据库事务中。

消息中的路径不能替代数据库中的可信状态。重复消息跳过已完成任务；任务已取消、超时或被新执行接管时，旧消费者不能覆盖新结果。

## 5. 成功与归档

确认产物上传成功及处理权有效后，在一个本地数据库事务内：

1. 锁定并核查文件、任务状态及本次处理标识。
2. 更新 media_files 的可用状态、产物路径和地址。
3. 更新任务完成信息并写入 media_process_history。
4. 删除 media_process 中的待处理任务。

归档失败不能留下“文件已可用但任务历史丢失”的部分提交。重复消息和并发完成不会重复归档。历史记录仍用于状态查询与文件引用核查，不能作为无用表删除。

当前 ConsumerServiceImpl.markAsSuccess 已包含行锁、处理标识核查、事务更新、历史插入和任务删除；重构时还需验证实际调用经过事务代理及失败回滚行为。

## 6. 失败重试与超时恢复

实际转码失败记录错误、失败次数及下次重试时间。达到最大次数后停止自动重试，保留任务和错误，允许有权限的老师处理或重新安排，不伪造成功。

定时任务识别超过转码超时加宽限时间的处理中任务，更新任务及文件状态并恢复调度；当前调度器采用转码超时加两分钟宽限。已删除或删除中的文件不得被补偿重新激活。

旧消费者完成时再次核查处理标识，防止超时恢复后的迟到结果覆盖新任务。数据库异常、消息重投、消费者退出和对象存储故障分别验证，不能仅依赖正常转码测试。

### 已确认的人工恢复规则

- 自动实际转码失败达到配置上限后停止重试，保留失败任务和错误信息。
- 老师可对本人教学空间的失败任务执行“重新转码”；处理中、删除中、已完成任务拒绝重复安排。
- 人工重试重置本轮失败次数，同时保留此前失败信息供查询。保留方式需在实现时设计，不能仅清空当前错误字段；无需提前删除现有表和字段。
- 状态更新事务提交后立即调用共用投递入口，投递失败由定时扫描补偿，消费者重新核查处理权。
- 第一轮不增加源文件替换功能。源文件有问题时上传新文件并重新绑定课程，仍遵守草稿、审核快照与正式发布版本规则。

## 7. 课程绑定与播放

Content 管理 teachplan_media 关联，校验课程归属、媒资归属与可用性。上传完成、转码完成、绑定课程是三个独立结果；普通编辑不能绕过审核快照和发布规则。

老师预览、管理员审核走授权入口；匿名试学仅允许正式发布且标记为试学的小节。其他播放由 Learning 核查有效资格，再由 Media 签发短期地址。对象存储保持私有，数据库中的对象路径不是永久公开播放链接。

## 8. 安全删除与恢复

删除前核查本人教学空间及课程草稿关联、审核快照、正式发布内容和共享产物引用。仍被引用时拒绝删除。绑定和删除之间存在并发窗口，实施需验证现有锁定及跨服务核查方式，不能只依赖前端提示。

进入删除中状态后取消转码任务，禁止新处理结果提交，再清理原文件、转码产物及相关记录。仍在运行的任务需等待取消或超时处理，不提前报告全部删除成功。

对象存储操作与数据库无法使用同一个本地事务：删除失败保留 delete_error 和删除中状态，重复删除按幂等方式恢复，已删除对象按既定规则处理。删除完成后才清理对应任务/历史记录；共享对象不得误删。

### 已确认的删除与恢复规则

- 草稿目录、有效审核快照或正式发布内容仍引用文件时拒绝删除；引用核查故障不能当作无引用。
- 标记删除中后禁止新绑定和新转码，并协调取消处理中任务；绑定与删除之间的并发保护需专门设计和验证。
- 清理原文件、转码产物及相关记录；共享对象仍被其他文件使用时保留。
- 清理失败保留删除中状态和错误，定时自动重试，默认每轮最多三次，间隔可配置。首次删除与补偿共用幂等清理入口，次数统计在实施时明确。
- 达到上限后老师可对本人文件执行“重试删除”，重新安排有限重试；文件不恢复成可绑定或可播放状态。
- 对象存储故障不能按删除成功处理；完成全部清理后才报告删除完成。

## 模块与数据边界

| 对象                           | 所属模块 | 用途                              |
| ------------------------------ | -------- | --------------------------------- |
| media_files                    | Media    | 文件归属、对象信息及可用/删除状态 |
| media_process                  | Media    | 待处理、处理中、失败及恢复任务    |
| media_process_history          | Media    | 成功任务历史、状态与产物核查      |
| 对象存储与 FFmpeg              | Media    | 原文件、分片、产物及转码执行      |
| teachplan_media、审核/发布快照 | Content  | 课程引用及冻结内容                |
| 学习资格与试学校验             | Learning | 决定学员是否可访问小节            |

Media 的 mq_message/mq_message_history 与上述转码任务表不同，目前仅发现实体/Mapper 定义，是否清理仍需外部依赖和实际数据库核查。转码归档与 Content 发布任务归档是独立流程。

## 与教程的取舍

沿用教程的上传、MD5 校验、分片续传、状态抢占、有限重试、超时补偿和成功历史归档。采用事务提交后立即投递、Spring 定时扫描补偿和 RabbitMQ 消费，不引入 XXL-Job。当前代码仍以扫描投递为主，立即投递及共用入口是待实现项。

教程公开存储桶示例不用于当前项目；保留私有对象存储与资格授权。文件删除扩展为引用保护、处理中取消、产物清理及失败恢复。用户已确认新增上传会话及默认七天无活动清理规则；该机制需要实现并验证，不能因教程提及定时清理就宣称当前已实现。

## 验收清单

- 普通上传、断点续传、缺片/错片、摘要和大小不符、重复合并及跨空间拒绝。
- 事务回滚不发消息；提交后立即投递；提交后进程退出或回调遗漏由扫描补发。
- 立即投递与扫描并发抢占、消息确认丢失、消息重复、发送失败恢复，以及多实例处理互斥。
- 转码失败重试耗尽及人工恢复；上传成功后发送失败不能要求重新上传。
- 消费者退出、处理中超时、旧消费者迟到、归档失败回滚和重复归档。
- 可用视频绑定、草稿/审核/发布引用保护、试学与有效资格播放。
- 转码与删除并发、对象删除失败、重复删除、共享产物保护和取消超时。
- 核查媒资/任务/历史记录与对象实际一致，执行相关构建、针对性测试、格式和 UTF-8 检查。
