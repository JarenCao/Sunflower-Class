# 普通上传与分片续传验收单

日期：2026-10-01。状态：技术验证通过，等待用户验收。本次只完成开发清单的上传与分片续传项。

## 结果

- 复用现有 API → Service → Model、MyBatis、MinIO SDK、Commons Codec 和媒资登记事务，没有新增依赖、业务表或架构层。
- 四个分片接口从已验签身份读取机构编号，分片路径包含机构编号。完整文件检查、合并登记与普通上传共用原有机构记录标识规则，兼容本机构旧 MD5 主键。
- 不合法 MD5、负分片号、超出 S3 上限的分片总数、空文件及空分片返回明确 HTTP 400，避免路径截取异常造成 500。
- 合并前检查全部分片，缺片提示具体编号并保留有效断点；合并后校验总字节数和整文件 MD5，真实大小写入媒资记录。校验失败清理损坏分片及合并对象，不创建媒资或转码任务。
- 登记失败清理本次上传或合并产物；合并登记失败保留有效分片，允许重试。原登记事务负责媒资与转码任务一致提交。原媒资缺失对象时拒绝覆盖/删除原记录，存储检查异常不当成“文件不存在”。
- 重复上传/合并复用本机构有效记录，不重复创建转码任务；转码后的文件按登记位置检查，不用原视频 MD5 判断转码产物。

## 实际验证

1. 57项有意义的实时断言通过，经过原机构/学员账号、真实 Vite 代理、Gateway、Auth、Media、MySQL 和对象存储；覆盖参数、权限、普通上传与重复上传、缺片保留、损坏清理、新会话续传、重复合并、原课程播放及待支付拒绝。
2. 原 MP4 增加合法 free 数据块生成本次独立验收视频，大小14,827,669字节，按前端5MiB分片拆为三片。先上传首片、模拟中断，再从真实媒资中心重新选择原文件。服务日志确认首片未重传，仅补传第二、第三片。
3. 实际读取对象存储，合并原文件字节数和 MD5 与本地文件完全一致；登记文件大小正确，成功后本机构全部三片已删除，媒资只新增一条。
4. 真实 RabbitMQ 与 FFmpeg 完成视频转码，媒资页面显示“转码完成”。这只证明本次成功流程，转码失败、重试次数和定时重试规则仍属于下一项。
5. 同长度篡改首片后上传其余分片，合并被整文件校验拒绝；真实数据库无对应登记，存储中损坏分片和合并对象均不存在。
6. 3项临时故障验证通过：对生产上传实现使用真实对象存储，仅将登记依赖替换成抛异常的临时测试依赖，验证普通上传产物清理、合并产物清理/有效断点保留及测试对象清理。未中断真实数据库、未注入线上触发器，未提交测试文件。
7. 外机构专用分片在本机构不可见，验证后已清理该临时对象。原9条媒资元数据与验收前快照逐字段一致，原已选课程仍可取得受保护视频地址，待支付课程仍返回403。
8. 后端编译和机构端生产构建通过；本次代码、中文注释及文档按UTF-8保存，并检查替换字符、连续问号及常见乱码模式。

## 人工验收

1. 使用原机构账号登录 [媒资中心](http://localhost:5173/media)，查看 upload-acceptance-普通上传.png 与 upload-acceptance-断点续传.mp4，视频应显示“转码完成”。这两条记录保留供验收，不绑定原课程。
2. 选择普通图片上传，再选择相同图片，确认列表只保留一条记录。
3. 选择较大的视频，点击“停止上传”，重新选择同一文件，确认可完成续传；在开始合并之后取消浏览器请求，并不表示能撤销服务端已经开始的合并/登记。
4. 缺片与损坏验证、登记失败注入结果、原数据快照及页面截图保存在忽略目录 .runtime/upload-acceptance-20261001。

旧的无机构分片目录不再复用，也不自动删除；重新选择原文件时会按新的机构目录上传，已登记有效媒资不受影响。对象存储清理异常会记录日志；本次未建设定时清理任务。确认本项验收后，再等待用户“继续”开发下一项。
