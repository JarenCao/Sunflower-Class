# 订单与支付宝沙箱验证记录

日期：2026-10-02。Orders 按原 API → Service → Model 三层接入独立 orders 数据库，经 Gateway 提供真实接口。**代码与本机关键测试通过，真实支付宝交易闭环尚未通过，暂不交付人工验收。**

## 实现行为

学员先选择收费课程，再由 Learning 返回可信课程、价格和有效期快照，Orders 创建 30 分钟待支付订单及商品/支付记录。忽略客户端伪造价格、用户和已支付状态；原生唯一索引与行锁保证并发创建只有一个有效订单。历史关闭订单保留，长整数订单号按字符串返回。

使用支付宝官方 SDK 生成沙箱二维码、查单、关单及 RSA2 验签。确认付款时核对应用、收款人、订单号、金额、交易流水及实际付款时间。缺配置返回 503，生成二维码不产生学习资格。订单和 Learning 数据库存 UTC，接口展示北京时间；付款必须在创建时间至截止时间的半开区间内。

付款状态与 payment_event 在同一 orders 事务保存；定时任务通过 RabbitMQ 持续重发至收到 Learning 回执。Learning 在同一事务校验原选课快照、记录 payment_processed 并开通资格；重复消息不会延长有效期。消费者提交后发送回执，失败通过重试/失败队列保留。前端提供订单列表、详情、二维码与状态查询，待支付课程可以继续付款。

## 重构已确认的订单超时与迟到通知规则

本节为用户确认的重构规则，不代表已完成新增实现或真实付款验收。

- 待支付订单默认三十分钟到期，期限可配置。到期先查询支付宝：已支付则确认交易；未支付则请求关闭，确认关闭后更新本地状态。
- 平台不可用或结果不确定时保留可恢复状态，不能直接标记关闭。
- 迟到通知按核实的实际付款时间判断；截止前成功付款仍正常确认并开通资格。核查签名、金额、应用、收款账号、流水，重复通知只处理一次。
- 已付款但 Learning 尚未开通时展示“已支付，学习资格开通中”，继续可靠事件及回执恢复，不用消息发送确认替代开通结果。
- 截止后付款或交易状态冲突进入异常核查，不自动开通，不丢弃交易记录。
- 第一轮不新增退款功能，真实沙箱付款及公网回调仍需独立验收。
