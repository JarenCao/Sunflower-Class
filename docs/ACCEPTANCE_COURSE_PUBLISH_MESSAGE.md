# 课程发布消息落库验收单

本次完成开发清单 P0 的发布消息持久化。内容服务复用已有 `MqMessage` 实体和 MyBatis-Plus，在 `publishCourse()` 的数据库事务内保存正式发布快照、课程状态和一条 `course_publish` 待发送消息。消息记录携带课程 ID、机构 ID、发布状态；执行次数和各阶段状态均从 0 开始。写入失败将抛错，使整个事务回滚。已经发布的课程重复请求不会产生新消息；下架后重新上架是新发布事件，保存新消息。

## 验收环境与检查

- 2026-09-29，Gateway 63010、Content 63040、Media 63050 及 WSL2 Docker 中的 MySQL、Nacos、Silo 正常运行。机构端 5173、学员端 5174 通过真实 Gateway 接口读取课程。
- 先只读核对真实 `sunflower_class.mq_message` 表字段：自增主键、消息类型、业务键、执行次数、总状态及阶段状态均与现有实体匹配。
- `mvn -f content/pom.xml install -DskipTests` 编译成功；未新增测试文件。

## 真实流程结果

1. 创建临时课程 152，添加视频小节并绑定已就绪媒资。发布前查询该课程待发送消息为 0 条。
2. 提审、审核通过、发布均成功。数据库同时存在状态 `30502` 的正式快照和消息 ID 4；消息类型 `course_publish`、课程 ID 152、机构 ID `1232141425`、执行次数及状态均为 0。
3. 重复调用发布后仍只有 1 条消息，正式快照的发布时间不变。
4. 下架后重新上架成功，出现第 2 条独立发布消息（ID 5）。机构端显示“审核通过 / 已发布”，学员端全部课程显示该课程。
5. 验收结束后下架并删除临时课程，按 ID 和课程 ID 精确清理这两条测试消息，不影响原有数据。

本次仅保存待发送消息；实际发送、重试与消费属于开发清单下一项。未通过人为破坏数据库模拟事务失败，回滚保证由现有 `@Transactional(rollbackFor = Exception.class)` 和抛错路径提供。技术联调与用户验收均已通过（2026-09-29）。
