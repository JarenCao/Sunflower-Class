# 独立认证服务与 users 数据库验收

日期：2026-10-01。状态：开发与真实联调完成，用户已确认验收通过。本次只处理登录微服务及已有数据库接入，未继续开发角色权限。

## 实现

- 按项目原三层架构组织：`auth_model`（DTO）→ `auth_service`（服务接口、实现及数据库认证业务）→ `auth_api`（HTTP 和启动配置）；实际依赖方向为 API → Service → Model。
- 登录入口从 Content 移至独立 `auth-api`，端口 63080，Nacos 注册、Gateway `/auth/**` 负载均衡路由、两端 `/api/auth` 接入。
- 使用 `users.user` 的 BCrypt、状态和新用户类型；从用户表或唯一机构关联读取机构，冲突时拒绝登录。用户类型不与通用状态码混用，管理员不默认获得机构身份。
- 添加失败计数及锁定时间字段，保留 JWT、Cookie、CSRF、中文密码 UTF-8 字节限制和凭据日志脱敏。
- 原始十个用户的密码及身份不变；此前两个验收账号保留在新库。历史 `auth_user` 保留但不再用于登录。

## 真实验证

通过两个 Vite 代理、Gateway、Auth、Content、Media 执行 37 项断言：登录、身份恢复、Cookie、错误密码、禁用账号、未知类型、五次失败锁定、UTF-8 密码长度、CSRF 缺失和伪造、无效 JWT、退出、学生隔离、管理员不继承旧机构、关联表回退、机构冲突及非 BCrypt 明文拒绝，全部通过。

浏览器实际完成机构登录、读取 28 门课程、刷新身份保持和退出；学员登录显示“验收学员”，刷新仍保持身份。公开搜索仍可匿名读取。

Auth 三层模块清理构建验证、Content 清理构建、Gateway 验证及两端生产构建通过。本次未新增提交用测试源码，实时断言脚本和结果位于忽略的 `.runtime/`。移除的旧 Content 登录控制器 class 文件已清理。Content 的通用异常处理目前把不存在的旧路径返回 500；前端已全部使用新路由，旧路由不再提供身份。本次未扩展修改无关异常处理。

## 用户验收

1. 在机构端 `/login` 使用原 `sunflower-institution` 验收账号登录，检查课程列表、刷新和退出。
2. 在学员端 `/login` 使用原 `sunflower-student` 账号登录，检查显示名、刷新和退出。
3. 也可使用导入数据库中启用、保存有效 BCrypt 的账号和其原密码：`itcast`、`Kyle` 为机构类型；`stu1`、`Lucy` 为学员类型。未重置或猜测原账号密码。

验收账号密码仅保存在本机 `.runtime/login-accounts.json`。七个临时负向验收账号及两条临时机构关联已清理，现有用户 12 个（原始 10 个加之前的两个验收账号），用户角色和机构关联均无孤立记录。源码、配置和文档严格 UTF-8 解码及乱码检查通过。

当前两个前端及 Auth、Gateway 和业务服务继续运行；完整角色权限在用户确认本项并要求继续后处理。
