# 课程审核操作验收单

日期：2026-09-28。状态：开发与前后端联调完成，用户于 2026-09-30 在 P0 阶段验收中确认通过，见 [P0 验收单](ACCEPTANCE_P0_INTEGRATION.md)。

## 本次实现

- 审核工作台按待审、通过、驳回状态分页查看课程；待审课程可通过或填写原因驳回，任一课程可查看历次审核记录。
- 后端仅允许待审且未发布课程审核。课程基础表、预发布快照和 `course_audit` 操作记录在同一事务更新；重复审核、空驳回原因、状态不一致均拒绝。
- 驳回课程不能发布，可以重新提审。重新提审会清空预发布快照里的上一轮审核时间和意见，历史记录仍保留。

## 实际验证

- Windows Maven 执行 `mvn -q -f content/pom.xml install -DskipTests`，机构端执行 `npm run build`，均通过；按当前约定未新增测试源码。
- WSL2 现有 MySQL、Nacos、RabbitMQ 和 MinIO 容器启动后，Gateway `63010`、Content `63040`、机构端 `5173` 可访问。
- 通过 Gateway 创建临时课程 `143`、`145`：提审后审核状态为 `30403`，未通过时发布被拒绝；空原因驳回被拒绝；正常驳回为 `30401`，重新提审、通过后为 `30404`，历史同时保留驳回及通过两条记录；发布后学员公开详情为 `30502`，重复审核被拒绝。
- 使用机构端页面处理临时课程 `144`：驳回后课程离开待审列表、出现在已驳回列表，审核记录显示原因、审核人与时间；重新提审并通过后课程出现在已通过列表，两次审核记录都可见。
- 临时课程 `141`～`145` 已通过接口删除；数据库复核显示课程、审核、预发布、正式发布和教学计划记录均为零。

页面截图位于本机忽略目录 `.runtime/review-acceptance.png`。

## 当前边界

审核人暂由服务端 `sunflower.reviewer-name` 标识，机构由 `sunflower.company-id` 配置；登录、审核员角色和权限控制仍属于开发清单的身份模块。当前接口不应作为生产环境审核权限保护。发布消息落库与消费属于后续功能。
