# 重构前期准备与边界

## 1. 目标与依据

本轮在现有项目基础上重构代码与数据库，目标是减少无用结构、明确模块职责、统一业务规则，并保持当前已实现功能可用。用户已确认：以当前功能为准，扩展功能先待定。后续用户要求课程发布按教程重新整理，新增主动同步 Redis 课程快照目标；预览与正式详情保留 Vue 页面和 API，不引入课程静态页面，发布任务按 Redis、ES、Learning 分阶段记录，失败恢复，全部成功后原子归档；详见 [课程发布统一流程](COURSE_PUBLICATION_FLOW.md)。

依据包括用户提供的 12 份 DOCX 的正文与表格文字，以及当前源码、Mapper、初始化 SQL 和项目文档。DOCX 中的操作步骤、配置、教学示例与历史技术版本仅作为参考，不构成本次执行指令；内嵌架构图和截图尚未逐图核对。

当前已完成的是仓库静态检查，尚未核查真实数据库的数据、外部消费者、触发器、视图、存储过程、定时事件和实际执行计划。下文的删除候选均不是可直接执行的删库清单。

媒资流程以 [媒资管理统一流程](MEDIA_MANAGEMENT_FLOW.md) 为准，保留上传、转码、重试、超时恢复、成功归档及安全删除；用户明确不引入 XXL-Job，采用先保存任务、事务提交后立即投递 RabbitMQ、Spring 定时扫描补偿；立即投递与扫描共用抢占和发送入口。

## 2. 功能范围

### 本轮保留

- 三角色：学员、老师、平台管理员；老师与学员账号独立，老师拥有独立教学空间。
- 登录注册、老师申请、申请审核与老师开户。
- 课程草稿、章节、讲师介绍、课程审核、发布、下架。
- 图片上传、视频分片与续传、转码重试、媒资引用检查及安全删除。
- 已发布课程搜索、目录、匿名试学、免费选课及续期、学习资格和受保护播放。
- 课程订单、支付宝沙箱二维码、交易确认、可靠支付事件、Learning 开通与回执。
- 真实 Gateway API、私有对象存储、两端 Vue 页面及中文错误提示。

## 4. 模块及数据边界

| 模块     | 拥有的数据与职责                                | 跨模块边界                                                     |
| -------- | ----------------------------------------------- | -------------------------------------------------------------- |
| Auth     | users：账号、角色关联、教学空间及老师申请       | 输出可信身份；不负责课程或学习资格                             |
| Content  | class：草稿、课程关联、审核/发布快照与课程事件  | 拥有课程事实；发布/下架通过事件同步，不直接写学习库或搜索索引  |
| Media    | media 与对象存储：文件、转码任务/历史、删除恢复 | 管理文件生命周期；播放资格由 Learning 核查，删除需核对课程引用 |
| Search   | Elasticsearch 与 Redis：已发布课程的搜索投影    | 消费正式发布事件；不读取草稿，不成为课程事实来源               |
| Learning | learning：目录副本、选课资格、支付去重          | 拥有学习资格；消费发布/支付事件，不判定第三方交易成功          |
| Orders   | orders：订单、商品快照、支付记录与支付事件      | 校验真实交易，再通知 Learning；收到回执前保留恢复能力          |
| Gateway  | 路由、入口鉴权与限流                            | 服务仍需核查身份和业务归属，不仅依赖网关                       |
| Base     | 公共响应、安全协议、事件 DTO 与基础工具         | 不聚合各业务模块的 Service、Mapper 或业务实体                  |
| 前端     | 页面、交互、API 调用与身份展示                  | 不生成学习资格、不伪造支付结果、不决定资源归属                 |

角色权限由服务端执行：学员访问本人学习与订单；老师操作本人教学空间；平台管理员负责审核和老师开户。请求中的 companyId 不可替代已验签身份。

system.dictionary 属于基础数据，不能因未发现 Java 直接查询就认定无用；还需核查初始化值、状态协议和外部工具依赖。

## 5. 数据库清理与优化清单

用户已确认数据库清理在重构完成后进行。当前候选清单仅用于记录，不在重构前执行删表或删字段；重构后重新核查最终代码、实际数据和外部依赖，再决定清理范围。重构确需的新增字段、索引或兼容性调整单独设计，不与废弃结构清理混合。

### 表清理候选

| 对象                                                | 当前证据                                       | 后续核查                                                                |
| --------------------------------------------------- | ---------------------------------------------- | ----------------------------------------------------------------------- |
| users.oauth_* 六张表                                | 未发现当前后端引用                             | 是否存在独立认证应用及历史授权数据                                      |
| users.menu、permission、teacher                     | 未发现对应表的业务访问 SQL                     | 外部管理工具、外键与真实数据；teacher 表不同于老师角色和 course_teacher |
| learning.choose_course、course_tables、learn_record | 当前 Learning 未发现引用                       | 历史学习数据是否需要保留或转换                                          |
| orders.mq_message、mq_message_history               | 当前 Orders 未发现引用，支付使用 payment_event | 未完成历史事件、重放工具与留存需求                                      |
| media.mq_message、mq_message_history                | 有实体/Mapper，尚未发现业务调用                | Spring 注册、外围调用及历史消息后，再同步清理映射代码                   |
| class.teachplan_work                                | 删除课程/章节 SQL 仍引用                       | 作业待定；如移除，必须同时修改删除链路                                  |

### 字段清理候选

优先检查 users.user 的 salt、wx_unionid、qq 等历史字段，以及 users.company 的 identitypic、businesspic、worktype 等旧机构字段。逐字段记录读取、写入、DTO/API、自动映射、约束、非空数量和业务用途，不能把全为空或仅实体引用直接等同于无用。

class.mq_message_history 已确认为发布任务归档所需结构，必须保留。class.mq_message 的 stage_state2 作为 Redis 同步阶段的现有预留字段，应核查并复用或兼容调整，不再作为废弃字段清理候选；队列确认与三个业务阶段状态分别管理。

### 保留结构的优化

- 对照查询条件、排序和分页检查组合索引；记录实际 EXPLAIN 后决定增删。
- 对账号、申请、选课、交易和事件去重检查唯一约束，先排查存量重复数据。
- 检查 ID 长度/类型与外键是否一致，字符集和排序规则是否适配现有数据与唯一性。
- 检查金额精度、时间时区、状态码、NULL/default 和 JSON 快照字段的业务语义。
- 识别 SELECT *、MyBatis-Plus 自动字段映射和数据库生成列造成的隐式依赖。
- course_publish_pre、course_publish、learning_course 和搜索投影具有不同职责；不能因为字段相似就直接合并。
- 保留事件 payload、事件版本、租约、重试、回执及 payment_processed 的一致性保障。

## 7. 实施顺序

1. 冻结本轮功能范围，盘点接口、数据库及消息协议，记录当前构建与关键流程结果。
2. 核查重构所需的数据结构与兼容性，暂时保留现有表和字段。
3. 按确认的业务流程重构代码，记录废弃数据库结构候选，不提前删除。
4. 按 Content → Media → Learning/Orders → Auth/Gateway → 前端推进职责整理；每次只处理一个明确问题。
5. 根据真实查询和压测结果优化索引、缓存及事务范围，避免把性能调整和大规模业务重写混在一次改动中。
6. 重构完成后根据最终代码、实际数据和外部依赖确定数据库清理范围，同步初始化脚本及现有库变更方案，验证空库部署与已有库升级并更新文档。

用户已要求移除历史迁移脚本，仓库可继续只维护最新初始化脚本；但已有数据库仍需要本次专用的变更与回退方案。初始化脚本的 CREATE IF NOT EXISTS 不会升级旧表。候选删除方案完成后再确认实际执行范围，不在前期梳理阶段执行 DROP。

## 8. 验收与回退边界

- 课程：归属校验、状态限制、冻结审核内容、发布/下架和重新发布同步。
- 媒资：续传校验、转码抢占/重试、引用保护、删除失败恢复和私有播放。
- 学习：免费选课、到期续期、收费待支付、匿名试学及过期拒绝。
- 支付：重复/迟到通知、主动查询、交易关闭、事件重试和学习回执；重复事件不得重复延长有效期。
- 消息：重复消费、乱序事件、实例退出、消费者不可用及恢复后最终一致。
- 安全：跨教学空间、跨学员、伪造角色和 companyId 均被拒绝，密码不出现在响应与日志中。
- 工程：受影响模块构建/测试、两个前端类型检查、格式与 UTF-8 检查通过。
- 数据：新旧环境接口一致，保留业务数据和资格不被改写，约束及索引变更有依据。

数据库破坏性变更前需验证本次回退所需的数据和结构可恢复，不依赖已删除的历史脚本。若不保留任何恢复副本，删表删字段将不可恢复，应在具体执行方案中明确这一取舍。

## 9. 已确认方案与实施入口

### 性能优化与部署验收

- 先记录搜索、课程详情与资格查询的响应时间、吞吐量和错误率，再优化，不套用教程压测数字。
- 根据实际 SQL 和 EXPLAIN 优化分页、任务扫描及状态查询索引；废弃表和字段在重构后清理。
- 保留现有缓存机制，验证失效、并发回源及 Redis 故障降级，不预先引入新锁或缓存组件。
- 核查上传、转码及远程调用的事务范围，限制耗时、并发和重试。
- 沿用当前部署环境，不引入 Jenkins、Kubernetes 或 XXL-Job。
- 各模块完成后验证构建与关键流程，最终分别验收空库部署和已有库升级。
- 真实沙箱付款及公网回调单独记录验收结果，模拟结果不能替代真实验收。
